# Donations (Solana, optional)

A gallery owner can turn on a donation button. Donations go to a wallet the server
creates and holds for that gallery; the owner withdraws to any Solana address. There is no
fundraising goal: the website shows the total donated, the number of donations and recent
donors.

Off unless `SOLANA_ENABLED=true`. Defaults to **devnet** (test money).

## Custodial model and its risks (read before mainnet)

- One keypair per gallery, generated by the server. The secret key is stored only encrypted
  (AES-256-GCM) with `SOLANA_WALLET_ENCRYPTION_KEY`, bound to the gallery and public key. It is
  never returned by the API, logged or sent over WebSockets. It is decrypted in memory only to
  sign a withdrawal.
- **`SOLANA_WALLET_ENCRYPTION_KEY` is the most sensitive secret of the deployment.** Lose it
  and every gallery wallet becomes unrecoverable; leak it together with a database dump and
  the funds can be stolen. Generate with `npm run solana:keygen`, store it in the host's
  secret manager, and back it up separately from database backups. Rotating it requires
  re-encrypting all wallets (not implemented).
- Holding funds for others can be regulated (money transmission) depending on jurisdiction.
  Get advice before `SOLANA_CLUSTER=mainnet-beta`; the server refuses mainnet unless
  `SOLANA_ALLOW_MAINNET=true`.
- Blockchain transfers are irreversible. There are no refunds or chargebacks.
- Use a dedicated RPC provider (`SOLANA_RPC_URL`) in production; public endpoints are rate-limited.

## Flow

```
Owner:   PUT  /v1/galleries/{id}/donations {enabled: true, message}     -> creates the wallet
Anyone who can view the gallery:
         GET  /v1/galleries/{id}/donations                              -> {enabled, address, totalSol, donationCount, recent[]}
         POST /v1/galleries/{id}/donations/intents {lamports?, donorName?, message?}
              -> {id, recipient, reference, solanaPayUrl, expiresAt}
         ...donor pays in their wallet...
         POST /v1/donations/{id}/confirm {signature}                    -> verified donation
         GET  /v1/donations/{id}/qr?format=svg                          -> Solana Pay QR for phone wallets
Owner:   GET  /v1/galleries/{id}/donations/wallet                       -> balance, withdrawals
         POST /v1/galleries/{id}/donations/withdrawals {requestId, destination, lamports | "all", password}
```

Amounts are integer **lamports** (1 SOL = 1,000,000,000 lamports); responses also give SOL as
a decimal string. Minimum donation: `SOLANA_MIN_DONATION_LAMPORTS`.

### Paying from the website (wallet adapter, e.g. Phantom)

Build a transfer to `recipient` and attach `reference` as an extra read-only, non-signer
key (the Solana Pay convention), sign and send, then report the signature:

```ts
import { Connection, PublicKey, SystemProgram, Transaction } from '@solana/web3.js';

const intent = await api.post(`/v1/galleries/${galleryId}/donations/intents`, { lamports, donorName, message });
const ix = SystemProgram.transfer({ fromPubkey: wallet.publicKey, toPubkey: new PublicKey(intent.recipient), lamports });
ix.keys.push({ pubkey: new PublicKey(intent.reference), isSigner: false, isWritable: false });
const signature = await wallet.sendTransaction(new Transaction().add(ix), connection);
await connection.confirmTransaction(signature, 'confirmed');
// Retry while details.reason === 'not_found_yet' (every 2 s, up to ~60 s).
await api.post(`/v1/donations/${intent.id}/confirm`, { signature });
```

Phone wallets: show the QR from `/v1/donations/{id}/qr` (it encodes `solanaPayUrl`); the
backend's poller detects the payment by its reference within `SOLANA_POLL_INTERVAL_MS`.

### Verification rules

A donation counts only if the transaction (read from the cluster at `confirmed`
commitment) succeeded, includes the intent's unique `reference`, and credits the gallery
wallet with at least the minimum and at least the requested amount. Each signature counts
once. Failures return `422 DONATION_UNVERIFIED` with `details.reason`: `not_found_yet`
(retryable), `transaction_failed`, `reference_missing`, `wallet_not_credited`,
`amount_too_low`, `signature_already_counted`. Verified donations are pushed to everyone
viewing the gallery as a `donation` WebSocket message.

Donor names and messages are optional, public, length-limited, and treated as untrusted
text (render as text; never passed to the assistant as instructions).

### Withdrawals

Owner only, password re-entered, at most `SOLANA_WITHDRAWALS_PER_HOUR` per gallery, one at a
time, idempotent by `requestId` (a retry returns the original withdrawal and never sends
twice). `"all"` sends the balance minus the network fee. Destinations must be valid on-curve
wallet addresses. If confirmation times out the withdrawal is marked `failed` with the error;
check the wallet on the explorer before retrying, because the transfer may still have landed.

## Testing

`test/donations.test.ts` runs the real encryption, verification and withdrawal code against
an in-memory ledger standing in for the Solana RPC (real keypairs; simulated network). A
manual devnet check: set `SOLANA_ENABLED=true` and a key, enable donations on a gallery, send
devnet SOL from a wallet such as Phantom (devnet mode, airdrop from https://faucet.solana.com)
using the snippet above, and confirm the signature.
